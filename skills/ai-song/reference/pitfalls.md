# 踩过的坑和做法

都来自一首歌（YuE2 为主，前奏结尾用 ACE-Step 1.5）。数字是那首歌上量的，换一首歌要重新量。

## 先记住四条

1. **生成便宜，返工贵。** 不要省生成次数，要省人试听的轮数。
2. **按这个顺序做：形式、接缝、贴合、咬字、混音。** 形式没定就修字，修的可能整段作废。
3. **听不见就量，但要说清这是测量。** 指标能发现问题、筛候选，判断不了好不好听。
4. **所有判断都放回整首里做。** 单独听或单独听写通过的，放进混音、加速之后可能不通过。

## 扒曲

这一节来自一次测试：拿一首手机录的参考歌，从扒曲做到写完词。

| 现象 | 原因 | 做法 |
|---|---|---|
| m4a 分离、分析时报 Format not recognised | librosa 1.0 以后只读 libsndfile 能读的格式 | 脚本先用 ffmpeg 解码（已改）；自己写脚本也这样做 |
| `separate.py --model parts` 报 No module named 'diffq' | audio-separator 里的 Demucs 加载时就导入 diffq | 装 diffq，或者让 `separate.py` 用 `scripts/stubs/diffq`；`check_setup.py` 会试导入这条路径 |
| 分离跑了几分钟，SSH 一断就没了 | 前台跑 | 挂在后台跑，输出写日志 |
| 按能量切出几十秒长的「一句」，说话也算成唱，音域多算了一大截 | 混响和串音把句子之间的空隙填满了；音高跟踪会跳八度 | 用听写的句子算（`transcribe_ref.py` → `analyze_ref.py --lines`），超过 8 秒的句子要查，说的部分单独算，八度跳错的音折回来 |
| 整首听写一遍，整段漏掉，还编出电视台名 | Whisper 在长音乐上会漏、会编 | 分窗口听写，窗口从换气处开始；只删编出来的那几个分句，同一段里真的词留下 |
| 漏的地方用更小的窗口重听，结果更糟 | 窗口越短越爱编，又在音乐中间开头 | 窗口不缩小；用 `--from/--to` 只重听那一段，`--merge-into` 并回去 |
| 唱的句子被切成两半，算出来的句长只有一半 | 句子跨在窗口边上 | 窗口边上相隔不到 0.25 秒的两段重新接起来（`transcribe_ref.py` 已做） |
| 速度候选里有一对正好 3:2 | 可能是 4/4，也可能是 12/8 | 看拍子判断：只比 8 个和 12 个八分音符哪个更像一小节；3+3+2 的重音律动照样是 4/4，单独标出来 |
| 唱和说分错：轻柔滑音的唱句被当成说话，慢慢说的对白被当成唱 | 按每秒几个字和长音多少分，两头都有例外；按「底下有没有伴奏」也试过，会把稀疏的主歌当成说话 | 只当提示，人听着改 |
| `analyze_ref.py` 跑了 4 分钟 | 整首人声上算音高（pYIN）最慢 | 只在听写出的句子上算；`--no-pitch` 跳过；它会打印每一步用时 |
| Windows 上 librosa 导入失败（numba 的 DLL 被拦） | 系统的应用控制策略 | 扒曲放到 Linux 机器上跑 |
| 风格卡写了「乐器名待人听核」，没人问，风格描述按歌词年代写了中国乐器，样片和参考歌一点都不像 | 扒曲后没停下来问人；乐器按题材推 | 扒曲完停下，请人答风格和标志性乐器；风格描述照参考歌和人答写，不照题材的年代、国别 |
| 节拍检测给的第一拍落在一段对白里 | 第一拍不是小节线 | 小节线从有鼓的地方猜，写进实测版歌曲地图前再核 |
| 调的前两名分数只差 0.01 | 和声简单，或者人声和伴奏的调号不一样 | 看「其他」那层的调和分窗口的结果；还是接近就待人听核 |
| 贝斯层整首没声音，鼓层看不到底鼓和镲片 | 手机或低码率录音录丢了 | 配器里低音和鼓的部分要人听着补 |
| 风格卡只给出乐器的角色 | 量不出乐器名字 | 乐器名字由人挑，或者你建议、人确认 |
| 要 30 秒，词写完一算要 45 秒 | 写词时没按速度和句长算时长 | 段落表折成秒，跑 `songmap.py --target` |
| 风格卡只量了速度和调，样片速度对上了，人说一点都不像 | 风格还在和弦走向、音阶色彩和律动里 | `harmony_groove.py` 量这三样，写进风格卡，样片再拿来比 |
| 在伴奏层上量不出 3+3+2，小节线也找不准 | 扫弦把每个八分音符都填满了；手机录音里几乎没有底鼓 | 律动在鼓层上量（`separate.py --model parts`） |
| 鼓层上跟拍，读出的速度只有真速度的 2/3 | 3+3+2 里跟上了三个八分音符一拍的脉冲 | 脚本会试 4:3、3:2 这几种，挑最能解释重音的那个（已改） |
| 同一段，伴奏层和「其他」层读出的和弦只有 25%–60% 的小节一样，伴奏层还把一段副歌读高了一个全音 | 伴奏层里有鼓和别的声音；手机录音 | 和弦在「其他」层上量；写进风格卡时标「测量，待人听核」 |
| `tag_ref.py` 把开头 3 秒几乎无声的一段标成长笛、R&B | 段落太短太静，标签没有意义 | 不到 5 秒、低于 -45 dBFS、比最响的段落低 35 dB 以上的段落跳过（已改）；`--plan` 先看 |
| Windows 上打印中文报 UnicodeEncodeError | 控制台编码 | `python -X utf8`，或设 `PYTHONUTF8=1` |

## 词和读音

| 现象 | 原因 | 做法 |
|---|---|---|
| 字读错（便宜唱成 biàn，宿唱成 sù） | 模型按常见读音唱 | 词里先标读音；只在生成规格里换成单一读音的同音字，歌词文件不动 |
| 换了同音字以后，文档和实际对不上 | 两份文字混着用 | 歌词文件是唯一的真相，同音字只写在生成规格里 |
| 句子长短不齐，字挤在一起 | 模型按行唱，不按小节排 | 写词时看字数；词定了就多出几版筛，还不行再和人商量改词 |
| 只差声调的多音字（中 zhōng/zhòng） | 唱腔本来就改字调 | 风险小；`forced_reading.py` 分不出来（Whisper 两种都写同一个字），要判只能靠人听 |
| 念白写在哪儿 | 歌词文件要是唯一的真相，念白又不能给作曲模型 | 写进歌词文件的 `[spoken]` 段，发给作曲模型前自动去掉 |

试过有用的替换：江滨→江冰，炖→顿或蹲，粮→凉，宿→修或休，贬→便，院→愿，便宜→骗宜或偏宜，掸→胆。

## 生成（YuE2）

| 现象 | 原因 | 做法 |
|---|---|---|
| 描述里写 90 BPM 出来 99，写 99 出来 93 | 描述里的速度不可靠 | 每版量小节长度（`take_grid.py`），再决定拉伸 |
| 描述里写了调，16 版落在 8 个调上，速度 98–118 | YuE2 不照描述的调和速度 | 第二段接着第一段唱（`keep_from`）；分开出的话，先用 `take_grid.py` 按调和速度筛 |
| 描述里写「一小节一句」，每句还是唱两小节，计划 47 秒出来约 65 秒 | 句长由歌词怎么排决定，描述管不住 | 量每句几小节再重算；要一小节一句就 `lines_per_row: 2` |
| 主歌要两句一行、副歌要一句一行 | `lines_per_row` 原来整首只能一个数 | 按段写 `{"verse": 2, "chorus": 1}`（已改） |
| 整段一次生成时，副歌每句只唱约 1.1 小节，计划是 2 小节；描述里写 long held notes 没用 | 副歌跟着主歌的字速走 | 见 SKILL.md 第 4 步第 8 点：试过什么、还有哪些没试过的想法 |
| 描述里写了「3+3+2 syncopated groove」，出来还是二四拍的反拍 | 模型认风格标签，不认乐理描述 | 写模型认得的风格名（SKILL.md 第 3 步的表，暂定）；出来以后用 `harmony_groove.py --compare` 量 |
| 照 CLAP 的结果写了「Latin pop」，出来是普通流行 | 大类的风格词把模型带到最常见的流行上 | 写最窄的风格名（比如 rumba flamenca），再加标志性乐器 |
| 词后面单写一个 `[Instrumental]`，模型照样唱：整首从头再唱一遍、即兴 16 秒、一直哼到结尾 | 模型不会在词唱完的地方停 | 用 `cut_take.py` 剪到最后一句后一小节 |
| 16 版里 5 版没唱完就停了 | `max_duration` 给少了，前面的哼唱又可能拖到 20 秒 | 计划秒数乘 2 再加 20 秒；量过句长后乘 1.2 再加 20 秒 |
| 唱到 `max_duration` 的版，不一定是被切了 | 很多版唱完词还在哼、即兴或者重唱 | 混音上的 `hit_cap` 只是提示；分离后用 `take_sections.py` 判 |
| 按人声能量量，每句 1.8–3.1 小节；按词量是 0.9–1.3 | 能量把前面的哼唱（最长 20 秒）、后面的即兴和整首重唱都算进去了 | 按词量（`take_sections.py`，再 `take_grid.py --sections`） |
| 伴奏层上跟拍读出的速度是混音上的 4/3（6 版里 2 版） | 3+3+2 的律动上，跟拍锁到了三个十六分音符一拍的脉冲 | 脚本会试 4:3、3:2 这几种（已改）；分离后伴奏和混音都量，对不上就标出来 |
| 带哼唱和重唱一起拟合小节线，误差 130–165 毫秒 | 哼唱、重唱的部分速度和正文不一样 | 只在有词的那一段上拟合（`--sections`），误差降到 4–13 毫秒 |
| 伴奏上读 135、混音上读 103，剪样片和量律动还是用了 135 的小节 | 脚本只认伴奏那一个格子 | take_grid 把混音的格子也存下（`grid_mix`）；混音对时 `cut_take.py`、`harmony_groove.py` 加 `--grid-from mix`（已改） |
| 同样压到 -1.2 dBTP，ACE-Step 的样片 -12.8 LUFS，YuE2 的 -16.4 | 两个模型出来的动态不一样 | 一起比的样片用 `cut_take.py --lufs` 对齐响度（已改） |
| 换了一台机器上现成的 ACE-Step 安装，跑不起来 | 原来的安装靠一组环境变量：离线、自己的缓存目录、Python 头文件 | `ace_step_run.py --runtime … --python-headers …` 自己设（已改），变量见 `models.md` |
| 每版的人声从 0 到 20 秒开始都有，统一一个起点去听写就错位 | 前面的哼唱长短不一 | `take_sections.py` 按词找每版的起点，`score_takes.py --sections` |
| 原始版峰值就是 1.0 | 生成时顶到满刻度 | 拼接、混音前先降电平；`take_grid.py` 会标出来 |
| 伴奏唱到最后一句就停了 | 模型以为歌结束了 | 歌词后面继续写内容（下一段，或 `[Instrumental]`）；逐小节查电平 |
| 想要一段纯器乐 | 模型默认要唱 | 下一段写 `[Instrumental]`，描述里写主奏乐器和 no vocals。人声降到约 −100 dB，拍子和原来那版对齐到 0 毫秒；不同种子常给出同一段旋律，它来自这版自己的前奏，所以接得上全曲 |
| 器乐段后面还有词，模型很快又开唱 | 它在赶词 | 只用开唱之前的小节，或者不写后面的词 |
| 从带鼓的一版接着唱，写了 no drums 还是有鼓 | 接着唱带着原来的惯性 | 要换配器，从更早的位置接，或者不接、重新出 |
| 同一段词想换唱法，总唱回原来的旋律 | 保留的 token 里已经有这段旋律 | 从这段之前的位置接，模型没听过它，才会找新的 |
| 描述里写「从容」，接着唱的速度还是不变 | 保留的 token 带着原来的律动 | 能改善落拍和音高，基本改不了速度；要真慢就从更早的位置重来 |
| 写 slowly，说话变得极慢 | 模型理解过头 | 少用这类词，生成后再调速（1.3 倍最清楚） |
| 重新渲染以后每句都变了 | 总时长一变，噪声就变 | 用贴片，不要整条替换；整版重渲染时保留除最后一个以外的全部 token（`rerender`），总长不变，句子之间的低谷都落在同一个 40 毫秒的格上 |
| 不知道怎么只换咬字、不动旋律 | 规格里没有整版重渲染的写法 | `{"rerender": "那一版", "render_seed": 新种子}`；原来的渲染种子当对照，一次测试里相关度 0.9999 |
| 整句重唱，重复的旋律丢了 | 旋律也跟着重新采样 | 保留到要修的字之前，只重唱后面 |
| 强制对齐把六个字打到接近 0，以为都唱错了 | 对齐的概率低不等于错：自由听写听对了其中两个，一个多音字其实唱对了 | 自由听写三个窗口里至少两个没听到才算错（`score_takes.py` 的 `wrong`）；对齐只用来找位置 |
| 一个字在所有渲染里都错（按上一行的算法） | 错在 token 里，不在渲染 | 换渲染种子没用；是多音字先跑 `forced_reading.py`，真错再从这个字前面重唱；一轮不行就问人接受还是改词 |
| Whisper 把「行」听成「让」，换成「航」重唱了 4 版，没有一版更好 | 唱对了，是 Whisper 听错了声母 | 换同音字重唱之前先跑 `forced_reading.py`：读出 háng 0.43，另两个 0 |
| 同一段音频听写两次，一句的分数差了 0.29 | 听写本身有噪声，约一句一个字 | 一个窗口的差别不算；看三个窗口里几个听到 |
| 从别的渲染贴一个字，混音里还是读错 | 贴片盖不过伴奏 | 贴完在混音里验证，没改善就撤掉，少一个接缝 |
| `keep_seconds` 等于 `max_duration` 时报错 | 没有可采样的空间 | 只重渲染时留一点差值，比如 83.96 对 84.0 |
| 新词想贴着原来的旋律唱 | 普通的接着唱不够贴 | 把原来前四句的 token 原样复制到 16 小节之后再接着唱，同音高的比例从 0.34 升到 0.50 |
| 换声模型（RVC）以后词听不清 | 变调损失清晰度 | 降 5 个半音后，听对的比例从 0.71 掉到 0.41；能不用就不用 |

## 拼接和伴奏

| 现象 | 原因 | 做法 |
|---|---|---|
| 两版独立生成的主歌和副歌，调一样、小节线对齐、拍子相位也对上了，人还是听出主旋律在中间换了 | 两次生成各有各的旋律想法，风格描述也不一样 | 副歌接着主歌唱；比形式时只比整段连着生成的样片 |
| 按估出的速度算小节线，14 小节后差了约 0.2 秒 | 节拍图上读出的速度是一格一格的近似值，差约 2% | 跟拍以后拟合一条直线求周期（`take_grid.py`），拼接用 `join_takes.py` |
| 副歌第一小节比主歌最后一小节低 6 dB 以上 | 两版生成的电平不同 | 按伴奏对音量，最多补 6 dB，补满了要人听 |
| 两段合不上（人说「音乐和节奏没接好」） | 速度不同还叠在一起 | 先拉到同一个速度，再按小节和循环位置硬接 |
| 拼完变调或乱拍 | 没对循环位置，或者两版不在一个调 | 拼之前量调；只看伴奏对齐；拼接点在四小节和弦循环的同一个位置 |
| 手工撤层以后伴奏断断续续、单调 | 手工编排代替了模型的伴奏 | 每段用生成时自带的伴奏，全曲不断 |
| 下一段进得太晚，中间像空了一块 | 原伴奏先停，后一段才进 | 把下一段同一循环位置的小节提前淡入，换掉原伴奏 |
| 拉伸以后字变了（粮变成脸） | 拉伸结果和前后的内容有关 | 每次把整条渲染一起拉伸再切，听到的就是打分时的那段音频 |
| 在能量低谷切开，一个字落到错的一边 | 低谷不一定是句子边界 | 切完把两边都听写一遍 |
| 估错句子位置 | 按行数推算 | 用 Whisper 的字时间，结合能量停顿核实 |
| 峰值报警 1.1，实际只有 0.84 | ffmpeg 混成单声道时读数偏高约 1.4 倍 | 在立体声上量峰值 |
| 声称是同一段音频的两段，拼起来低音变薄、变轻 | 时间舍入差了 4 毫秒，低音反相 | 拼之前算相关系数，低于 0.98 就停下查 |
| 段落调了顺序，结尾收不住 | 原来不是结尾的段落，伴奏到时长上限就断了 | 各段在同一个四小节循环上时，整段对调很便宜；查人声空隙、伴奏切点和新结尾有没有收住，收尾另外补 |
| 拍子检查前后矛盾：一版前奏按拍子量 0 毫秒过了，好的那版 270 毫秒没过 | 3+3+2 律动里第二拍后半拍的重音把按拍子量的读数拉偏最多半拍；而且重音错开了几个八分音符，八分音符的格子照样对得上 | 在八分音符上量相位，再比每小节的重音要错开几个（`beat_check.py`）：那版前奏要错开 3 个，好的那版是 0 |
| 结尾的拍子读出 +52 到 +139 毫秒 | 新写的只是一个扫弦的长和弦，没有脉冲可量 | 看新写的第一下离小节线多远：-20 到 +3 毫秒 |
| 新前奏最后半小节被标成安静 | 原版自己在那里就有一个停顿，还更安静 | 安静的小节先和原版同一位置比（`bar_levels.py --ref`，`assemble.py` 自己比） |
| 要 -16 LUFS，又要真峰值不超过 -1.5 dBTP，只调增益到不了 | 原版副歌的一个重拍顶着峰值，整首只能到 -16.9 LUFS | 真峰值说了算，报差多少、峰值在哪；要补就 `assemble.py --limiter`（一次测试里 0.09 秒里最多压 1.4 dB，到了 -16.0），用了要写明 |
| 拼成品只能照着别的歌的例子改 | 没有通用的拼接脚本 | `assemble.py`：前奏、这一版的伴奏和人声、结尾、念白都按小节线拼，参数可以写进 `song_map.json` |

人声拉伸用 rubberband 的 `transients=crisp:detector=compound`，咬字明显好于 `smooth`。

## 念白和哼唱

| 现象 | 原因 | 做法 |
|---|---|---|
| 念白总被唱出来 | 作曲模型没有「说话」模式 | 念白用语音模型单独生成再混进去 |
| 念白处很难听、像空了 | 整段伴奏压低 7.5 dB，形成约 10 dB 的低谷 | 只在每句话下面短暂压低，念白放在旋律的长音上 |
| 开头的念白放在音乐上不自然 | 克隆的声音放在音乐上，效果不够好 | 我们最后删掉了开头念白，只留间奏里一句 |
| 念白放多响、伴奏压多少，没有数 | | 起始值：和副歌人声一样响，只压伴奏 4 dB，80 毫秒斜坡；一次测试里念白比底下的伴奏高 4.9 dB，混音里三个窗口都听到 |
| 念白在最后一个长音上，第 6 步混不进去 | 结尾还没做 | 第 6 步生成、挑好，第 7 步拼的时候混（`assemble.py --spoken`） |
| 数字人 skill 的 `tts_qc.py` 查不了一句设计出来的声音 | 它要一个参考声音，也不查音高 | `spoken_qc.py`：错字率、语速、音高中位数，混完在混音里再听写 |
| 语音模型的环境和模型文件夹要手工找 | 它常装在单独的环境里 | `check_setup.py --for tts` 会找出来 |
| 哼唱出不来 | 从句子结束后接着生成会断 | 从一个正在唱的音接着往下，歌词写「嗯」 |

## 前奏、结尾和点缀（ACE-Step 1.5）

| 现象 | 原因 | 做法 |
|---|---|---|
| 单独生成的器乐点缀叠上去接不上 | 没有拍子，也不跟和弦走（音准差 2 音分也没用） | 用 repaint 从原伴奏往外长 |
| repaint 两小节几乎写不出东西 | 太短 | 写四小节；结尾常在三四小节内自然落下 |
| 只要一小节的尾巴 | | 也写三小节，让它自己落：一次测试里 8 版有 7 版在小节线上撤掉乐队，0.9–1.9 小节内落定 |
| 补了前奏，才发现这一版自己就有 4 小节前奏 | YuE2 的版常常自带前奏 | 先看自带的能不能用（电平、有没有哼唱），能用就当一个候选，一个接缝都没有（`assemble.py --intro own`） |
| 修字时分离占了显卡时间的大半（23 分钟里 13.7 分钟） | 每个候选都整版分离 | 只分要贴的那几秒：`separate.py --start --end` |
| 想加一种乐器，用了 lego | XL 模型会把整段重画一遍，新乐器混在里面分不开 | 点缀用 repaint，不用 lego |
| 新写的二胡有破音 | 生成本身的毛刺 | 降 CFG：同种子下 CFG 7 降到 5.5，相同音符只剩 0.88，降到 2 只剩 0.53，干净程度没变；步数加倍也没用。用 Demucs 分出主奏那层，只在那层削尖峰、压高频（`smooth_lead.py`） |
| 收尾分几次生成再拼，人说「怪」「衔接不自然」 | 接缝太多：鼓在小节中间被拉掉，最后一个字后面空一下，铺底又回来 | 从要变的那一小节起一口气写到底，只给前面的上下文；两头都给上下文时，它会一直带着鼓 |
| 想让结尾自己撤鼓 | 12 版里只有 1 版在小节线上撤了鼓 | 多出几版；不用分轨，看 6 kHz 以上的频段比前几小节低多少就知道鼓在不在 |
| 在人声下面加副旋律，多数版本把最后一个字下面的和弦换了 | 模型不知道人声在哪 | 筛的时候比较每半小节的根音和原伴奏，查副旋律和人声每个八分音符是不是撞成半音或三全音 |
| 分离模型标成「人声」的，其实是笛子 | 笛子长音像人声 | 交给人听，或者选没被标成人声的 |

## 渐慢

| 现象 | 原因 | 做法 |
|---|---|---|
| 整段混音一起拉慢，人说「像是磁带坏了」 | 辅音、滑音、转音都按同一个倍数被拉慢，混响也被拉糊 | 人声不带混响单独用 WSOLA 拉，只拖长元音和换气；混响拉完再加；伴奏单独拉；从鼓停的小节线开始（`ritard.py`） |
| 慢得太多 | 照表演研究的曲线一直慢下去 | 曲线只决定怎么开始慢，停在哪个速度听人的：我们最后只慢 6%–9% |

## 评估

| 现象 | 原因 | 做法 |
|---|---|---|
| 听写全对，人还是说「怪」 | 只查了词，没查节拍和和弦 | 交付前跑 `fit_check.py` |
| 单独的人声读得对，混音里变了（摆变搬，笑话变香花） | 伴奏遮蔽 | 词要在混音里判 |
| 听写出「字幕志愿者」「请不吝点赞」之类 | Whisper 在音乐上编造，给了提示词更容易 | 删掉编出来的那几段；一个窗口大半是编的就作废，换窗口重跑，不当成低分 |
| 听写出「词曲 某某」（一个真实词曲作者的名字），还算进了分数 | Whisper 在哼唱和词后面的音乐上编出歌曲署名 | 「词曲」「作词」「作曲」「编曲」这类加进编造的清单（已改，词里真有这几个字时不算）；只听有词的那一段 |
| 从 0 秒开始听写，有前奏的版本全是编造 | 前奏没有人声 | 从第一句词开窗（`score_takes.py --sections`） |
| 从哼唱开窗，三个窗口全是编造 | 哼唱没有词 | 同上；没有 `sections.json` 时，它会换下一段人声再试 |
| 窗口停在副歌后 1 秒，末尾多出「谢谢观看」 | 窗口最后是音乐 | 只删编出来的那一段（已改） |
| 一版咬字很清楚的副歌，`take_sections.py` 只找到 1 句，`score_takes.py` 却听对了 99% | 盖住副歌的那个 20 秒窗口被 Whisper 整个编成电视台署名，删掉以后那三句就没了；只重听那几秒，它又编 | 从前面某一句听到的词开头，用 20–40 秒的长窗口重听，多听到了词才留（`take_sections.py` 自动做，已改） |
| `harmony_groove.py --compare` 把真有安达卢西亚终止的样片判成和弦没对上 | 它把参考歌副歌的和弦读成了别的套路 | 参考歌的和弦走向人核过以后钉上（`--pin` / `--ref-chords`）；没钉的和弦只算一半，不能单独定结论（已改） |
| 同一版的鼓，一个读法说 3+3+2，另一个说半拍感 | 按固定的小节起点算，小节线猜偏几个八分音符就读错 | 判定用转一圈找最像位置的读法，固定位置的也打印（已改） |
| 一段没找到，样片就被判成不要 | 量漏了当成没对上 | 判成「没量到」，先修计时再比（已改） |
| 同一版换个窗口，读法不一样 | 听写本身不稳 | 至少三个窗口，看每个字命中几次 |
| 把「又美的嘴」当错字 | 和「又没得罪」只差声调 | 转成拼音比较，去掉声调，in/ing、en/eng 合并 |
| 器乐段的和弦匹配分很低，旋律其实很好 | 主奏改变了频谱 | 直接打印主奏的音（`lead_notes.py`），在 16 分音符格子上看动机和长音 |
| 听写直接写出「宿」，看不出唱的是哪个音 | 多音字 | 强制选择（`forced_reading.py`） |
| 打分脚本静默失败 | 依赖没装，错误被吞掉 | 打分脚本不屏蔽错误输出 |

## 还没解决

- 改不了已经唱好的说唱的速度，只能后期拉伸整段音频。
- 不能直接指定旋律的音符，只能多出几版再按音高筛。我们试过自己写谱交给歌声合成模型唱，人听了觉得「太怪」：谱里几乎没有换气，三度跳太多，长短太匀。
- 好不好听没有指标。
- 和弦走向用文字指定不了。下一个想法，还没试过：自己写一条引导伴奏，用 MIDI 写和弦走向和律动（自己写的，绝不用参考歌的音频、旋律或伴奏），渲染成音频，当音频提示交给模型。ACE-Step 的 cover 和 repaint 本来就拿一段音频当输入（`ace_step_run.py` 的 cover 任务）；YuE2 能不能接外部音频，还要查。
- 副歌唱得比计划短时，还没有试出可靠的办法把它拉长（见 SKILL.md 第 4 步第 8 点）。
